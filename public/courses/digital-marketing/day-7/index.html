SEO from zero to advanced · Day 7 of 30

Technical SEO

4 hours

Find and fix the technical problems that stop pages being crawled, indexed or loading fast, using Search Console, Screaming Frog and PageSpeed Insights.

Lesson 35 minExample 25 minTasks 180 min≈ 4.0 h total

1Lesson

Technical SEO is the plumbing of a website (fitting, given our client). Nobody admires it, but when it breaks, nothing else works.

1. Crawling and indexing

Item What it is What to check
robots.txt A file at /robots.txt that tells bots what not to crawl That it doesn't block important pages or the whole site (Disallow: /)
XML sitemap A list of the pages you want indexed, usually /sitemap.xml That it exists, lists only live pages, and is submitted in Search Console
noindex tag Tells Google not to index a page That it isn't left on by accident (a common mistake after a site launch)
Canonical tag Tells Google which version of a duplicate page is the main one That each page points to itself or the right original
Status codes 200 OK, 301 moved permanently, 404 not found, 5xx server error Broken links (404s) and redirect chains
HTTPS Secure connection Every page loads on https:// and HTTP redirects to it

A simple robots.txt:

User-agent: *
Disallow: /cart/
Disallow: /admin/
Sitemap: https://northfieldplumbing.ca/sitemap.xml

2. Google Search Console (free, essential)

Verify the site (a DNS record is best: it covers every version of the domain), then use:

  • Pages report: which pages are indexed and why others aren't.
  • URL Inspection: test a single page, see how Google sees it, request indexing after big changes.
  • Sitemaps: submit the sitemap.
  • Performance: clicks, impressions, average position and the queries people used.
  • Core Web Vitals and HTTPS reports.

3. Crawl the site with Screaming Frog

Screaming Frog SEO Spider crawls a site like Googlebot and lists every URL with its status code, title, description, H1, word count, canonical and more. The free version crawls up to 500 URLs, which covers most small business sites. Export and sort:

  • Missing or duplicate titles and descriptions
  • Missing or multiple H1s
  • 404s and redirect chains
  • Pages with very little content
  • Images over 200 KB

4. Page speed and Core Web Vitals

Google measures real-user experience with Core Web Vitals. Good scores:

Metric Measures Good
LCP (Largest Contentful Paint) How fast the main content appears 2.5 seconds or less
INP (Interaction to Next Paint) How quickly the page responds to taps and clicks 200 ms or less
CLS (Cumulative Layout Shift) How much things jump around while loading 0.1 or less

Test with PageSpeed Insights. The usual fixes: compress and resize images (WebP), lazy-load images below the first screen, remove unused apps and plugins, use good hosting, set image dimensions so nothing jumps.

5. Mobile

Google mainly uses the mobile version of a site to rank it. Check: readable text without zooming, buttons that are easy to tap, no content hidden on mobile, no pop-ups covering the page.

6. Structured data (schema)

Schema is code that tells Google exactly what's on a page: a business, a product, a review, an FAQ, an event. It can make results richer and helps search engines (and AI assistants) understand the business. Add it as JSON-LD in the page <head>:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Plumber",
  "name": "Northfield Plumbing",
  "url": "https://northfieldplumbing.ca/",
  "telephone": "+1-519-555-0142",
  "image": "https://northfieldplumbing.ca/images/van.jpg",
  "priceRange": "$$",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "120 Example Rd",
    "addressLocality": "London",
    "addressRegion": "ON",
    "postalCode": "N6A 1A1",
    "addressCountry": "CA"
  },
  "areaServed": ["London", "St. Thomas", "Strathroy"],
  "openingHours": "Mo-Su 00:00-23:59"
}
</script>

Test it with Google's Rich Results Test and the Schema Markup Validator. Only mark up what's actually visible and true on the page.

7. Prioritise fixes

Not every warning matters. Fix in this order: anything blocking indexing → broken important pages → speed problems on key pages → duplicate titles and content → nice-to-haves.

2Worked example

Riya's technical check of Northfield (one afternoon).

  • Search Console Pages report: 14 pages "Excluded by noindex tag". The web developer had left noindex on the service pages after a redesign. Fixed in five minutes; the biggest win of the whole project.
  • Screaming Frog: 9 broken internal links to old URLs → 301 redirects added. 22 pages with the same title "Northfield Plumbing" → unique titles written.
  • PageSpeed Insights (mobile): LCP 5.8 s. The homepage hero was a 4.1 MB photo. Resized to 1600 px WebP (180 KB) → LCP 2.1 s.
  • Schema: none → Plumber schema added to the homepage and contact page, validated.
  • Sitemap: existed but listed 30 old URLs → regenerated and resubmitted.

Within three weeks, the 14 service pages were indexed and impressions in Search Console tripled.

3Today's tasks

✓By tonight you'll have

A prioritised technical SEO issue list from Search Console, Screaming Frog and PageSpeed Insights, plus validated schema.

★Tip

After any website redesign, check for leftover noindex tags and broken redirects first. It's the most common reason a business's traffic suddenly drops, and the fastest fix you'll ever bill for.
