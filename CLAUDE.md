# SchoolAura — notes for Claude

Static site for schoolaura.com. No local dev environment: changes are made by Claude, pushed to GitHub, and Vercel deploys `public/` automatically.

## Rules
- Edit sources, not generated HTML: courses in `content/*.md`, pages in `content/pages/*.html`, books in `vault-src/*.md`, templates in `templates-src/*/index.html`. Then run the matching script in `build/` and commit `public/` too.
- Design: light, simple, Skool-style (off-white canvas, white cards, Figtree). Tokens live at the top of `public/assets/css/site.css`, with one colour per course (drop orange, ai blue, mkt purple, vault rose, web green, vp amber for Viral Prompts) used only for covers, icons and progress. Keep new UI on those tokens.
- Card covers are rendered by `build/covers.py` (needs the local server on :8765). Fonts are self-hosted in `public/assets/fonts`.
- Never show the owner's personal details (name, address, email, phone, other businesses) anywhere on the site or in downloads. The brand is SchoolAura.
- Never invent reviews, testimonials, student numbers or results. Sample reviews exist only inside templates and are labelled as samples.
- Course content: plain English, short sentences, Canadian context where relevant, task lines end with `(N min)`.
- Progress is in `localStorage` under `sa.course.<slug>` (`done`, `tasks`, `quiz`, `notes`, `feel`, `certDate`); streaks, badges and the daily question are in `sa.engage`, the certificate name in `sa.name`. Logged-in users' copies sync to Supabase (`auth.js`); new progress keys must start with `sa.course.` or be added to `SYNC_RE` there.
- Membership is switched by `MEMBERSHIP` in `build/build.py` (`accounts`, `live`); see README "Membership". Server code is `middleware.js`, `api/*.js` and `lib/*.js` (no dependencies besides `@vercel/functions`; `lib/site-config.js` is written by the build, commit it with `public/`). Never put lesson text, task lists or prompt text into public JS files: lesson pages carry their own content and the middleware locks them. Keep previews honest (no fake urgency) and keep Day 1 free.
- Run `npm test` after changing `api/`, `lib/`, `middleware.js` or `auth.js`. Never commit a build made with `SA_LIVE=1` or `SA_ACCOUNTS=1` unless you're switching membership on for real; rebuild plainly first.
- Secrets (Stripe keys, webhook secret, Supabase secret key) live only in Vercel environment variables, never in the repo.
- Quizzes are in `content/quizzes/<slug>.json`. Every question needs a `why` and a `day` inside its module; keep them answerable from the lesson text. Lesson tools are `{{tool:name}}` lines, defined in `public/assets/js/tools.js`; example numbers in a tool should match the lesson's worked example.
- Lessons are static pages at `/courses/<slug>/day-N/`; course data is in `courses/<slug>/course-data.js`. Never link lessons with `#day-N` (old links redirect). Calendar, quizzes and about stay on the course page as `#plan`, `#quizzes`, `#about`.
- Viral Prompts packs are JSON files in `content/prompts/` and must follow `content/prompts/README.md` (original wording, no real people except the user's own photo, no named artists, studios, brands or characters). A scheduled task adds packs; check `git log content/prompts` before editing them. Its build also rewrites `lib/site-config.js` (the newest packs are the free ones), so that file is committed with `public/`.
- Keep SEO intact: every new page gets a unique title, description, canonical and (where it fits) JSON-LD through `head()` in `build/build.py`, and appears in the sitemap and search index.
- Pricing is set in `PRICING` in `build/build.py` ($9/month or $19 lifetime, CAD before tax, 30-day guarantee; `half` prices for the countries in `lib/pricing.js`). `MEMBERSHIP["live"]` off = early access (everything free). Never add fake reviews, customer counts or crossed-out "was" prices to the sales page; only use numbers the build can count. Legal pages are `content/pages/terms.html`, `privacy.html`, `refunds.html`; keep them in step with how payments and data actually work.
